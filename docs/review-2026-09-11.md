# 代码审查：2026-09-11

范围包括 Go 转发链路、CLI / macOS 共用连接、设备生命周期、Android API 兼容性、iOS 入口及构建配置。维护者已自行验证项目可用性，本轮按要求未重复真机或端到端测试。

## 已修复

- **P1：取消不能解除阻塞读取。** `RunConfig` 在握手和已连接阶段可能一直等待字节流，导致暂停、退出或超时清理不完成。补上覆盖整个连接周期的取消关闭，并限制握手等待时间。两个阶段的回归用例修复前均失败，修复后通过。
- **P1：usbmux 描述符的并发关闭及所有权。** 原实现直接关闭 Go 管理的 fd，且关闭与读写并发修改字段，存在二次关闭复用 fd 的风险。保留 Darwin 的阻塞 syscall 兼容路径，增加关闭同步、唤醒阻塞读写，并由原 `net.Conn` 释放它自己的描述符。Linux 使用标准网络连接。回归覆盖并发关闭、读取解除阻塞和原连接关闭状态。
- **P1：iOS 监听入口没有限制对端。** 原来绑定所有接口后直接替换当前客户端。现校验对端为 loopback 或本机接口地址，排除其他 LAN 主机；此变更已通过 iOS 编译，未做真机复测。
- **P2：旧连接清理影响重新插入的设备。** 按设备等待旧循环完成后再处理重插；按 serial 筛选时，也处理只有 ID 的 usbmux detach 事件。退出时等待转发循环释放资源。
- **P2：状态同步连接残留。** Hub 关闭所有客户端连接，确保查看状态的进程能检测到断开；释放所有权前等待 Hub 停止，清理 viewer 的取消回调。
- **P2：控制操作缺少取消和超时。** ADB 控制读写跟随 context 关闭，名称查询、forward 和 killforward 有时间上限；lockdown 查询也在取消时关闭字节流。TCP / UDP 上游连接在隧道结束时关闭。
- **P2：PCAP 文件在重连或多设备下损坏。** 每次连接重复写文件头，且不同连接的记录锁彼此独立。现整个 relay 共用一个 Capture，串行写入完整记录；增加并发记录校验。
- **P2：DNS TCP 长度头可能被拆分。** 两字节长度头改为 `io.ReadFull`，避免一次短读后使用不完整长度。
- **P2：重连后的速率发生无符号下溢。** 替换统计对象时重置差分基线，并检查计数器回退；增加回归用例。
- **P2：Android 5.x API 不兼容。** 两处无版本保护的 API 23 `getSystemService(Class)` 改为兼容调用。VPN 的 `systemExempted` lint 误报采用 service 局部抑制并在 manifest 注明[官方 VPN 豁免依据](https://developer.android.com/develop/background-work/services/fgs/service-types#system-exempted)，没有增加闹钟权限。
- **P2：Android 失败路径无法恢复界面。** 捕获 VPN 建立及监听失败、将握手写入包含在连接异常处理内、发布停止状态以结束界面的“准备中”。心跳改用固定延迟，避免后台恢复时补发积压任务。
- **P2：iOS 旧 IPC 回调跨连接回放。** 回调检查客户端代次；手动停止同时关闭容器 App 的 relay。
- 更新 README 的安装步骤、实际 iOS 路径、共享进程行为和当前边界，标明原设计文档的历史性质。

## 保留的后续项

- **P2：设备监听连接失效后不会重新订阅。** `adb.Watch` / `usbmux.Watch` 结束后，`relay.Run` 不会自动重建监听。当前可重启电脑端恢复；README 已注明。后续可添加带退避的监听重建与设备状态清理。
- **P2：iOS on-demand 与手动停止的持久化策略。** `TunnelPreferences.prepare()` 开启了 on-demand，`stop()` 只停止当前 VPN 和 relay，没有持久化关闭 on-demand。系统之后可能再次启动 extension；后续需要明确手动停止是否同步取消自动连接，并统一异步配置保存与再次启动的顺序。
- **P2：Android 同一 Service 实例的快速停止 / 启动。** 工作线程仍共用 `running`、TUN 与 socket 字段。若 VPN 绑定使实例保留，旧线程清理可能与新会话交错；后续应按会话隔离资源并等待旧线程退出。
- iOS relay 的写入仍使用阻塞 socket；若本机代理持续不读取，可能占住串行队列。后续可添加有界发送队列与写超时。

这些后续项没有通过本轮真机测试验证，不应将编译或单元测试通过解读为它们已经解决。
